# EKPO-LAB 优化方案（2026-10-28）

本方案基于三路输入：仓库代码审计、GitHub 同类开源项目对标（Senaite LIMS、
eLabFTW、OpenELIS Global、Chemotion、LabKey、RSpace）、全球公开权威数据库
与标准（PubChem、ChEMBL、NIST Chemistry WebBook、GHS 紫皮书 Rev.10、
ISO/IEC 17025:2017、ECHA），以及实验室软件与 B2B 控制台的 UX 规范
（整卡可点击标准做法、状态可视化、WCAG 2.2）。

## 一、本轮已落地（2026-10-28）

### 1. 点击无法直接跳转 —— 已修复并通过真实点击回归
根因不在主导航（8 个模块与视图一一对应、未知 tab 会被拒绝），而在总览
驾驶舱（`assets/js/ekpo-operations-cockpit-v3.js`）的跳转能力只有「一级 tab」
一个维度：

- **校准入口落点错误**：任务流「校准核验」、待核验队列「核对校准证据」、
  KPI「有效校准证据」点完只到设备维保页的「设备台账」子视图。现
  `data-ekpo-open` 支持 `maintenance:calibration` 形式直达子视图。
- **快捷操作名实不符**：「＋ 登记气体批次 / 设备 / 备件流水 / 测试日志」
  点完只是换页。现支持 `data-ekpo-modal`，跳转后直接打开对应登记弹窗；
  空状态「登记第一台设备」同理。
- **字符串 ID 行操作失效**：备份校验允许行 ID 为字符串，但气体、测试日志、
  系统全量表的编辑/删除渲染用了 `Number(id)`（字符串变 NaN）甚至未加引号的
  `${row.id}`（点击直接 ReferenceError）。已统一改用维保/备件在用的
  `labInlineId()`，`editGas` 补了不存在守卫（原先直接抛 TypeError），
  `editGas`/`editTestDiary` 的查找改为与 `deleteItem` 一致的 `sameLabId()`。
- **列表行不可点击**：驾驶舱设备/测试/气体三类列表行原本是纯展示
  `<article>`。已整行可点击（含 hover/focus 样式、Enter/空格键盘激活）。

防回归：新增 `scripts/validate-navigation-clicks.cjs`（需 Playwright，
与 `browser-ekpo-smoke.cjs` 相同运行方式：本地 4173 端口起服务后运行），
逐个真实点击上述入口并断言落点与弹窗，全程断言无页面错误。原有
`npm test`（51 项）与 `npm run check` 不受影响、继续全过。

### 2. 桌面版 —— 已生成
新增 `desktop/`（Electron 壳）：因应用以相对路径加载 ES 模块，
`file://` 下会失败，壳内以本地 HTTP 服务（固定 127.0.0.1:17361，
保证 localStorage 账本 `lab_management_db_v9` 跨启动持久）托管页面。
`desktop/build-windows.cjs` 一条命令打出 Windows x64 便携版
（免安装、解压双击 `EKPO-Lab.exe`）。限制：默认图标、无代码签名
（SmartScreen 首次提示）、数据仍为本机单用户。

## 二、对标提炼（值得长期遵循的规范）

- **三段式导航**（eLabFTW / Senaite / Benchling 共同模式）：模块入口
  （卡片带数量/风险角标）→ 列表（搜索 + 状态筛选 + hash 深链）→ 详情
  （返回时保留筛选与滚动位置）；全局搜索与全局新建各只有一个入口
  （本项目已有 Ctrl/⌘K 命令面板，方向一致，应补齐其条目截断问题：
  当前 collect 去重后 16 条、render 只取前 12，长标签模块进不了列表）。
- **状态机只给允许的下一步**（Senaite 样品五步生命周期）：本项目实验
  生命周期已部分做到（禁止未来日期的状态迁移）；可推广到校准与维保：
  证书过期/质控失败的设备应被标记 invalid 并阻止开启新实验——
  实验 preflight 已有准备度检查，可把「校准过期」从提示升级为硬阻断。
- **详情即枢纽**（SciNote）：设备详情应聚合其校准记录、维保历史、
  关联实验与备件消耗，而不是散落在各列表中靠人工对照。

## 三、全球数据库与标准接入路线（按价值排序）

1. **PubChem（首选，免费 PUG-REST API）**：气体/化学品建档时按名称或
   CAS 号拉取 GHS 分类、信号词、象形图与 LCSS 摘要，结果缓存进本地
   台账并标注来源与抓取日期。注意边界：PubChem 不能替代供应商 SDS。
   本项目是离线优先的本地应用，接入应为「手动触发、结果落本地、
   断网可查缓存」，不要做成每次打开都联网。
2. **SDS 五件套台账规则**（ECHA/REACH 口径）：每条化学品记录存
   SDS 链接、供应商、货号、修订日期、核对日期；同 CAS 不同浓度分条建档。
3. **ISO/IEC 17025:2017 第 6.4 条字段对齐**：设备唯一 ID、校准记录
   （6.4.13e）、维护记录（6.4.13g）、校准间隔要有依据、状态标识防止
   误用超期设备、发现超差要处置并回顾既往结果。本项目字段已大体齐全，
   缺口在「状态标识」与「超差回顾」流程。
4. **NIST Chemistry WebBook**：无公开 API，仅做外链参考（物性数据核对）。
   ChEMBL 与日常台账关系弱，暂不接入。GHS 采用紫皮书 Rev.10 编码
   （GHS01–09 象形图、Danger/Warning 信号词、H/P 编码）进数据模型。

## 四、后续优先级清单（8 项，含验收标准）

| # | 事项 | 验收 |
|---|---|---|
| P0-1 | 其余可点击卡片按整卡规范收尾：标题内唯一链接 + 伪元素扩展点击区，卡组用列表语义，焦点框与 hover 同视觉（实验页计数卡、年度页统计卡目前不可点，应改为点击即筛选对应表格） | 键盘仅 Tab 一次到达整卡；筛选结果与卡片计数一致 |
| P0-2 | 状态三件套：颜色 + 图标 + 文字，禁止只靠颜色；列表默认按风险排序（过期 > 待核验 > 正常） | 关闭颜色（灰度）仍可分辨状态 |
| P0-3 | 设备校准按 17025 补「状态标识 + 过期硬警告」：实验 preflight 遇校准过期设备硬阻断 | 过期设备无法通过 preflight |
| P1-4 | 化学品建档接 PubChem + SDS 五件套 + 「缺 SDS」筛选 | 断网时缓存可查且标注来源日期 |
| P1-5 | 首页强化待办流：Jump back in（最近 8 项）+ 待核验队列按风险排序（驾驶舱已有雏形） | 首页 3 秒内能定位未办事项 |
| P1-6 | 详情关联区 + hash 深链（`#maintenance/calibration` 等），刷新/分享链接不丢位置 | 刷新后停留在同一子视图 |
| P2-7 | 时间线升级为不可编辑审计流（时间戳/对象/动作/前值→后值） | 任何记录变更在时间线可追溯 |
| P2-8 | 移动端触控收尾：目标 ≥44×44px、hover-only 操作给常驻入口、遵守 prefers-reduced-motion | 移动端无 hover 依赖 |

## 五、结构债备忘（不阻塞，按需处理）

- 11 个 CSS 文件多代层叠，含无渲染出处的死样式（如
  `product-system.css` 的 `.product-workflow__*`）；改样式前先确认层级，
  长期应合并收敛。
- 全站内联 `onclick` + innerHTML 拼串：与严格 CSP 冲突，桌面壳因此未
  启用 CSP；也是本轮字符串 ID bug 的温床。新代码优先事件委托。
- `npm run check` 只串了 11 个校验脚本中的 4 个，其余靠 CI 的
  validate workflow；新增校验时记得两边同步。
